### 💡 Key Takeaways & Upgrades We Can Adopt into ULPF

Here are the top **5 high-value improvements** we can adopt to enhance our codebase and maximize evaluation scores for SIH:

#### 1. Merkle-Tree Batch Tamper-Evidence (*Satisfies NTRO's "Blockchain" Theme*)
* **The Insight**: Running a full blockchain node for every log entry destroys throughput ($10k+$ events/sec). However, NTRO lists the theme as **Blockchain & Cybersecurity**.
* **What to Add**: A lightweight **Merkle Batch Integrity** module. 
  - Compute `SHA-256` for each raw event.
  - Every 1,000 events or 5 seconds, compute a **Merkle Root** over the hashes and store it in SQLite/ClickHouse.
  - *Result*: Provides cryptographically verifiable tamper-evidence for forensic audits without performance overhead.

#### 2. Lossless Overflow Field (`raw_unmapped`)
* **The Insight**: When mapping vendor logs to a canonical taxonomy, rare or vendor-proprietary keys might not have a direct canonical field.
* **What to Add**: Add an unindexed JSON overflow field named `raw_unmapped` to our normalized event object. Any unmapped vendor attributes land in `raw_unmapped`, guaranteeing **100% zero information loss** ($a$).

#### 3. Declarative Hot-Reload Parser Rules (JSON/YAML Schemas)
* **The Insight**: Onboarding new log sources ($e$, $i$) shouldn't require recompiling Java code.
* **What to Add**: Store parser transformation schemas in SQLite as JSON/YAML rules. When an admin approves a candidate mapping in the UI, `core-engine` hot-reloads the active rule definition into memory dynamically.

#### 4. Header-Based Format Autodetector
* **The Insight**: Fast deterministic format routing before parsing avoids trial-and-error parsing failures.
* **What to Add**: Add a lightweight header inspector at the ingestion entry point:
  - `<PRI>` $\rightarrow$ Syslog (RFC 3164 / 5424)
  - `{ ... }` $\rightarrow$ JSON
  - `CEF:0|` $\rightarrow$ Common Event Format
  - `LEEF:2.0|` $\rightarrow$ Log Event Extended Format

#### 5. Local Parquet Export for AI/ML Data Lakes ($g$, $h$)
* **The Insight**: Data science and ML teams prefer bulk Parquet files over raw SQL queries for offline model training.
* **What to Add**: Add an automated batch exporter endpoint `/v1/analytics/export/parquet` to dump ClickHouse log chunks into partitioned Parquet files for air-gapped ML pipelines.
