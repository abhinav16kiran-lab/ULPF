# Universal Log Framework (ULPF)
## Database Schema

## 1. Database Split

```text
                    ULPF
                     │
          ┌──────────┴──────────┐
          ↓                     ↓
       SQLite               ClickHouse
    control plane            data plane
```

### SQLite

ULPF-owned control state:

```text
users
vendors
sources
credentials
mapping_versions
onboarding_requests
notifications
```

### ClickHouse

For the prototype:

```text
ONE ClickHouse INSTANCE
ONE ClickHouse CONTAINER
        │
        ├── ulpf_raw
        │     └── raw_events
        │
        └── ulpf_events
              └── runtime canonical tables
```

Two logical databases do not provide separate CPU/RAM resources.

# 2. SQLite Schema

## `users`

| Column | Type | Purpose |
|---|---|---|
| `user_id` | UUID/TEXT | Unique user identifier |
| `username` | TEXT | Login username |
| `password_hash` | TEXT | Hashed password |
| `role` | TEXT/ENUM | `ADMIN`, `VENDOR`, `USER` |
| `created_at` | TIMESTAMP | Account creation time |

Constraints: `user_id` primary key; `username` unique.

## `vendors`

| Column | Type | Purpose |
|---|---|---|
| `vendor_id` | UUID/TEXT | Vendor identifier |
| `owner_user_id` | UUID/TEXT | FK → `users.user_id` |
| `vendor_name` | TEXT | Vendor organization |
| `status` | TEXT/ENUM | `ACTIVE`, `SUSPENDED`, `REVOKED` |
| `created_at` | TIMESTAMP | Creation/approval time |

Relationship: `users 1 : 1 vendors` for the current ownership model.

## `sources`

| Column | Type | Purpose |
|---|---|---|
| `source_id` | UUID/TEXT | Source identifier |
| `vendor_id` | UUID/TEXT | FK → `vendors.vendor_id` |
| `source_name` | TEXT | Source name |
| `source_type` | TEXT | e.g. FIREWALL, WEB_APP, DATABASE, SENSOR |
| `status` | TEXT/ENUM | `ACTIVE`, `SUSPENDED`, `REVOKED` |
| `created_at` | TIMESTAMP | Creation time |

Relationship: `vendors 1 : N sources`.

## `credentials`

| Column | Type | Purpose |
|---|---|---|
| `credential_id` | UUID/TEXT | Credential identifier |
| `source_id` | UUID/TEXT | FK → `sources.source_id` |
| `key_hash` | TEXT | API-key hash |
| `status` | TEXT/ENUM | `ACTIVE`, `REVOKED` |
| `created_at` | TIMESTAMP | Creation time |

Relationship: `sources 1 : N credentials`.

## `mapping_versions`

| Column | Type | Purpose |
|---|---|---|
| `mapping_id` | UUID/TEXT | Mapping identifier |
| `source_id` | UUID/TEXT | FK → `sources.source_id` |
| `version` | INTEGER | Source-specific mapping version |
| `mapping_json` | TEXT/JSON | Source → canonical mapping |
| `status` | TEXT/ENUM | `CANDIDATE`, `ACTIVE`, `RETIRED` |
| `created_at` | TIMESTAMP | Creation time |

Constraint: unique `(source_id, version)`.

## `onboarding_requests`

| Column | Type | Purpose |
|---|---|---|
| `request_id` | UUID/TEXT | Request identifier |
| `user_id` | UUID/TEXT | FK → `users.user_id` |
| `source_id` | UUID/TEXT/NULL | FK when applicable |
| `request_type` | TEXT/ENUM | `NEW_VENDOR`, `NEW_SOURCE`, `SCHEMA_UPDATE` |
| `sample_metadata` | TEXT/JSON | Uploaded-sample metadata |
| `status` | TEXT/ENUM | `SUBMITTED`, `AI_ANALYSIS`, `HUMAN_REVIEW`, `APPROVED`, `REJECTED` |
| `created_at` | TIMESTAMP | Request time |

## `notifications`

| Column | Type | Purpose |
|---|---|---|
| `notification_id` | UUID/TEXT | Notification identifier |
| `user_id` | UUID/TEXT | FK → `users.user_id` |
| `title` | TEXT | Title |
| `message` | TEXT | Body |
| `read` | BOOLEAN | Read state |
| `created_at` | TIMESTAMP | Creation time |

## `mapping_embeddings`

Stores embeddings associated with canonical fields for the local semantic mapping layer. The team has agreed that this table is part of the baseline schema from the start; the exact implementation/storage mechanics remain to be finalized.

| Column | Type | Purpose |
|---|---|---|
| `embedding_id` | UUID/TEXT | Unique identifier for the stored embedding. |
| `canonical_field` | TEXT | Canonical field/concept represented by the embedding. |
| `model_name` | TEXT | Name of the embedding model used to generate the embedding, e.g. `all-MiniLM-L6-v2`. |
| `model_version` | TEXT | Version/revision of the model used to generate the embedding. |
| `embedding` | BLOB / implementation-defined | Stored embedding vector; BLOB is the current proposed SQLite representation. |
| `created_at` | TIMESTAMP | Time the embedding record was created. |

The model name and version are stored so embeddings generated by different model versions are not treated as interchangeable.

### SQLite hierarchy

```text
users
  │
  ├── 1:1 → vendors
  │          │
  │          └── 1:N → sources
  │                       ├── 1:N → credentials
  │                       └── 1:N → mapping_versions
  │
  ├── 1:N → onboarding_requests
  └── 1:N → notifications
```

SQLite foreign-key enforcement should be enabled by the application.

The SQLite schema is ULPF-owned. Future ULPF-owned schema changes may use controlled migrations.

# 3. ClickHouse Raw Schema

## `ulpf_raw.raw_events`

```sql
CREATE DATABASE IF NOT EXISTS ulpf_raw;
CREATE DATABASE IF NOT EXISTS ulpf_events;

CREATE TABLE IF NOT EXISTS ulpf_raw.raw_events
(
    event_id         String,
    vendor_id        String,
    source_id        String,
    lineage_id       String,
    mapping_version  Nullable(UInt32),
    received_at      DateTime64(3) DEFAULT now64(3),
    raw_payload      String
)
ENGINE = MergeTree
PARTITION BY toYYYYMM(received_at)
ORDER BY (vendor_id, received_at, event_id);
```

## Columns

| Column | Type | Purpose |
|---|---|---|
| `event_id` | String | ULPF-generated physical raw-event identifier |
| `vendor_id` | String | Vendor identity |
| `source_id` | String | Source identity |
| `lineage_id` | String | Raw event/group represented by a normalized record |
| `mapping_version` | Nullable(UInt32) | Mapping version associated with processing |
| `received_at` | DateTime64(3) | ULPF receipt time |
| `raw_payload` | String | Complete original event |

`event_id` is an identifier, not a PostgreSQL-style uniqueness constraint under ordinary `MergeTree` semantics.

# 4. Runtime Canonical Tables

Examples only:

```text
network_events
web_events
authentication_events
database_events
sensor_events
```

These are not all preloaded. The deployment-specific canonical schema is created/extended only after approved changes.

Every runtime-created **event-derived** table must contain:

```text
event_id
lineage_id
```

This is a traceability rule, not a rule that every possible reference table must contain those fields.

# 5. Runtime Schema Lifecycle

```text
AI proposal
    ↓
Human approval
    ↓
Schema Manager
    ↓
controlled CREATE / ALTER
    ↓
ulpf_events
```

Customer-specific runtime schema changes are not stored as one ULPF migration file per vendor.

The initial ClickHouse bootstrap creates the logical databases and raw storage.

# 6. Persistence

### SQLite

```text
Spring Boot container
       ↓
persistent volume
       ↓
ulpf.db
```

### ClickHouse

```text
ClickHouse container
       ↓
persistent volume
       ↓
ClickHouse data/state
```

Container recreation must not remove persistent database state.

# 7. Runtime Lineage Example

Ordinary event:

```text
event_id = E123
lineage_id = E123
```

Sensor aggregation:

```text
E001 → L900
E002 → L900
E003 → L900
        ↓
N500 → L900
```

Backtracking:

```sql
SELECT *
FROM ulpf_raw.raw_events
WHERE lineage_id = 'L900'
ORDER BY received_at;
```
